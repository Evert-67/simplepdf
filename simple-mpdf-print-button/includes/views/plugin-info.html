Your content. Your document layout.

Design reusable templates

Use HTML, mPDF-compatible CSS and content shortcodes. Duplicate templates or move them between sites with JSON import and export.

Place buttons where they belong

Use automatic placement, a Gutenberg block or a shortcode. Choose a fixed template or let visitors select one.

Control the result

Choose opening or downloading, set a filename pattern, and adjust button colours, size and icons.

Get started in four steps

  1. Upload the installable Simple PDF ZIP through Plugins → Add New → Upload Plugin, then activate it.
  2. Open Simple PDF Print, create a template and add your HTML/CSS.
  3. Choose preview content and click Save & Test PDF. The preview opens in a new tab while the editor remains open.
  4. Publish the template and add a PDF button to a page.

Use the installable release ZIP, not a source-code archive. The installable package includes mPDF and its fonts. Requirements: WordPress 6.3+, PHP 8.0+, mbstring and gd.

Shortcode examples

Replace 123 with your published template ID. These are code examples, not live buttons.

A simple PDF button

[print_pdf_button template="123" label="Create PDF"]

Download with an icon

[print_pdf_button template="123" label="Download PDF" icon="download" output="download" size="large"]

Let the visitor choose a template

[print_pdf_button template="0" label="Create PDF" align="center"]

Choose the width and alignment

[print_pdf_button template="123" label="Open PDF" output="inline" align="right" width="250px" class="my-pdf-button"]

In Gutenberg, use the PDF button block for the same options. Set the page's PDF button placement to None when using a manual button to prevent duplicates.

A minimal PDF template

Paste this into the template editor, then use Save & Test. The tokens are replaced with the selected page's content.

<style>
body { font-family: sans-serif; color: #243b40; }
h1 { color: #225f6a; }
</style>
<h1>[post_title]</h1>
<p>[site_name] · [post_date]</p>
[post_content]

Other useful template shortcodes include [site_logo width="100"], [post_author], [post_excerpt] and [pagebreak]. Set a logo in your theme before using [site_logo]. For page headers and footers, use mPDF's supported HTML/CSS syntax.

Website frameworks style the button on your site. PDF layout is controlled by the template and mPDF; browser CSS features are not all supported.

Useful settings

Filename patterns

Use {site}-{title}-{date}. Available tokens: title, id, date, site and template, enclosed in braces. The PDF extension is added automatically.

Template defaults

Automatic buttons use the page's explicit template first, then the post-type default, then the global default. Manual buttons retain their own selection.

Common questions

Where are my templates stored?

Templates and their HTML/CSS are stored in your own WordPress database. Installing a plugin update does not delete them. They are not included when another person downloads the plugin.

Can visitors use every template?

Published templates can appear in the template selector. Keep unfinished or internal-only designs as drafts. PDF generation also checks access to the source content; membership plugins may require an additional integration.

Does Save & Test change the download setting?

No. It always requests an inline preview in a new tab. Visitor buttons follow the configured output setting. Browser preferences can affect how PDFs open.

Are images included in a template export?

No. JSON exports include template code, descriptions and categories. Images and fonts remain linked; move those files separately when migrating a site.

Where is the full manual?
